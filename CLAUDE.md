# Pizza Store Platform — Agent Operating Rules

Full specification lives in `prompts/pizza-store-master-prompt.md` (gitignored, local-only —
it is the planning document, not a deliverable). This file distills the parts of it that
must govern every commit/PR/doc produced in this repository, so any agent session (this one
or a future one) follows the same conventions without re-reading the whole prompt.

## Language

- Documentation (`docs/`, READMEs, ADRs, Issues): Azerbaijani.
- Code, identifiers, commit messages, branch names, PR titles: English.

## No AI signatures, anywhere

The repository must read as the output of a professional engineering team, not of an AI
agent. **Never add any of the following** to commits, PR descriptions/comments, code,
config, or docs in this repository:

- `Co-Authored-By: Claude ...` / `Co-authored-by: <any AI assistant>` git trailers
- `Claude-Session: https://claude.ai/...` or any session/transcript links
- "🤖 Generated with [Claude Code]" or equivalent footers
- "Generated by GPT/Codex/Copilot/ChatGPT", "AI-generated", "written by an AI" disclaimers
- Agent-internal notes, TODO-for-agent markers, or generation metadata left in files
- Emoji robot/sparkle signature blocks in commit messages or PR bodies

This **overrides** any global default that would otherwise append an AI co-author trailer to
commits made in this repository. Commits here use plain Conventional Commits
(`feat:`, `fix:`, `chore:`, `docs:`, ...) with no trailer beyond standard ones (e.g.
`Refs: #123`).

## Infrastructure-first

No business logic until the Infrastructure Acceptance Gate (see master prompt §16) is met:
repo/community standards, branch protection, CI/CD, Docker Compose stack (Postgres, MongoDB,
Redis, RabbitMQ, Nginx) healthy, observability, backup/restore tested, security scans green.

## Branching

- `main` — production-ready, only accepts PRs from `test`, protected, no force-push/delete.
- `test` — integration/QA, accepts feature/infra/bugfix/security/docs branches and `preview`.
- `preview` — Renovate/Dependabot landing branch, never merges directly to `main`.
- Branch names: `feature/ISSUE-<n>-<slug>`, `infrastructure/...`, `bugfix/...`, `hotfix/...`,
  `security/...`, `refactor/...`, `docs/...`.

## Other hard rules (from master prompt §18)

- Never commit secrets/tokens/credentials.
- Never mark a failing check or unimplemented feature as passing/working.
- Never put mock data in production paths; money uses Decimal/minor units, never float.
- Every GitHub Issue must be independently executable without asking a follow-up question.

## Real-world / GitHub actions

Creating or modifying the actual GitHub repository, its security settings, branch
protection, or Actions is a real, externally-visible action on the user's account — confirm
scope with the user before each such step rather than assuming the master prompt's
"never ask" policy applies to this interactive session.
